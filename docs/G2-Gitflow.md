# G2 – Working with Gitflow and Branches

## Objective

The objective of this task is to demonstrate how Gitflow can be used to organize software development through different branches and pull requests.

## Gitflow Structure

In my CarSimulator project, I used the following branches:

- **main:** Contains the main project code and merged changes.
- **develop:** Used for integrating changes during development.
- **feature/add-tests:** Used for implementing unit tests.
- **feature/github-actions-tests:** Used for configuring and testing GitHub Actions and Azure deployment.

## Development Workflow

I worked with separate feature branches to develop new functionality without directly changing the main branch.

After implementing changes, I used GitHub pull requests to review and merge the work.

This approach helps keep the development process organized and makes changes easier to track.

## Benefits of Gitflow

Using Gitflow provides several advantages:

1. New features can be developed independently.
2. Changes can be reviewed before merging.
3. The main branch can remain more stable.
4. Developers can track the history of each change.
5. Different development tasks can be organized into separate branches.

## Conclusion

Through this project, I demonstrated how to work with Git branches, feature development, pull requests, and merging.

I gained practical experience using GitHub to manage source code and organize a development workflow.
